# OnlyOne 个人工作台

单机、单人、离线的本地工作台：统一检索本地 Word/Excel/PPT、扫描件、爱数同步盘目录、企微在线文档链接、富文本记事本与运维问题记录，并在本机保存账号密码。

技术栈对齐 ACMNG 的架构（FastAPI + pywebview + Vue 3 + Naive UI），代码独立编写。设计见 `docs/设计方案.md`，真实界面截图见 `docs/screenshots/`。界面为**暖纸主题 + 左侧一级导航**，配色规范见设计方案 §8。

## 运行

开发期两个进程：

```powershell
cd D:\WorkBuddy\onlyone\backend
py -3 run.py --no-window --port 8765

cd D:\WorkBuddy\onlyone\frontend
npm install
npm run dev
```

生产形态（单进程窗口，自动启用文件监听）：

```powershell
cd D:\WorkBuddy\onlyone\frontend
npm run build
cd ..\backend
py -3 run.py
```

`run.py` 随机选空闲端口、生成一次性令牌（仅本进程有效），前端从 URL 取令牌后放进 `X-OnlyOne-Token` 请求头。API 只监听 `127.0.0.1`。桌面窗口创建失败时自动降级到系统默认浏览器，也可手动加 `--browser`。

## 打包（文件夹交付）

```powershell
cd D:\WorkBuddy\onlyone
py -3 build.py
```

产物在 `dist\OnlyOne\`（**111.2 MB**）：`OnlyOne.exe` 与 `frontend\dist\`、`data\` 同级。**整个文件夹一起拷走**即可离线运行，不是单 EXE。

`OnlyOne.exe` 用 `--noconsole` 打包（PE Subsystem=2），**启动不再弹命令行窗口**；代价是没有控制台输出，所有异常写 `data\onlyone.log`（`run.py` 已做 `sys.stdout is None` 兜底，并把 uvicorn 自带日志配置关掉）。需要另存产物目录时用 `py -3 build.py --dist-dir dist_next`，可保留旧产物不被覆盖。

## 数据与日志

- 数据库：`D:\WorkBuddy\onlyone\data\onlyone.db`（打包形态下在 EXE 同级 `data\`）
- 日志：`D:\WorkBuddy\onlyone\data\onlyone.log`（超过 2MB 轮转成 `.log.1`）
- OCR 字形模板缓存：`data\ocr_templates.npz`（首次使用自动生成，约 1.5 MB）
- 笔记图片附件：`data\attachments\<note_id>\`；全库备份：`data\backups\`

凭据使用 Windows DPAPI 加密，绑定当前 Windows 账户，无需主口令。数据库被拷到别的账户或机器上无法解密；同一账户下的其他程序仍可调用系统解密，请勿在不可信环境运行。**凭据不进全文索引**，列表中账号/链接/备注常显、**密码默认掩码**（点该行密码列的眼睛图标才展开，刷新或离开页签立即恢复）；编辑弹窗的密码框不再回填明文，留空即「不修改」。

### 索引库体积维护

`fts_entries` 是 FTS5 trigram 索引：条目更新都是 `DELETE` + `INSERT`，死段与空闲页不会自动归还。
实测 1367 条条目时库文件 309 MB，其中有效数据只有 108 MB。维护手段有两级：

| 方式 | 触发 | 效果 |
|---|---|---|
| 自动 | 每次扫描任务结束后，空闲页 ≥16 MB 且距上次 ≥1 小时 | 后台线程做 `optimize` + `VACUUM`，实测 109.8→108.9 MB，约 4 秒 |
| 手动 | `py -3 tools/db_maintenance.py`（**先退出 OnlyOne**） | `optimize` + `VACUUM`，实测 309.1→108.1 MB（回收 65%），6 秒 |

阈值可用环境变量覆盖：`ONLYONE_COMPACT_MIN_FREE_PAGES`（默认 4000 页 = 16 MB）、
`ONLYONE_COMPACT_MIN_INTERVAL_SEC`（默认 3600 秒；`0` 表示每次扫描后都做）。
`--no-vacuum` 只合并索引段不动磁盘；`--dry-run` 只打印指标。
压缩前后检索结果与条目数不变（`integrity_check` + FTS `integrity-check` 已校验）。

## 概览页（2026-11-25）

不带 `?tab=` 深链接打开时默认落在「概览」，替代原来的空搜索框；`Ctrl+K`、`?tab=xxx` 与各页跳转行为不变。

- **四个区块全部只读**：最近改动（`files.mtime` 倒序 8 条，点击进只读预览）、待跟进运维（未关闭按挂起天数升序，点击直达编辑弹窗）、最近笔记（排除私密页）、系统状态（库体积 / 上次备份 / 监听目录 / 扫描状态）。所有点击走既有 `jump` store，不在概览页开第二套编辑入口。
- **一个聚合接口**：`GET /api/overview?days=7&limit=8`（`backend/onlyone/overview.py`）。单块查询失败只降级该块并写入 `warnings`，HTTP 恒 200；`days` / `limit` 越界按边界夹取而不是 422。
- **性能**：新增 `idx_files_mtime`（写在 SCHEMA 里，老库启动自动补），最近改动查询 233ms → 3.9ms；`maintenance.stats(include_counts=False)` 跳过 fts 大表统计，体积块 167ms → 1.5ms。整页约 34ms（1361 文件 / 113 MB 实测）。
- **超期提醒**：`status='open'` 且距 `occurred_at` 超过 7 天（用 `>`，恰好 7 天不算；格式非法的记录不参与）。两处呈现——概览的「待跟进运维」卡片，以及运维记录表格的浅黄行（`BizCrud` 的 `row-class` 钩子 + `styles.css` 的 `tr.row-overdue`，项目工作台内嵌的运维表同样生效）。
- **点最近改动 = 带上文件名跳搜索**：`jumpToEntry(id, 文件名去扩展名)`，搜索页会自动以它检索并同时打开预览；关掉预览后停在结果列表，不会落到空搜索页。关系抽屉、项目「关联文件」里的跳转同样带标题，行为一致。
- 刷新策略：挂载拉一次 + 手动刷新 + 切回窗口且距上次 >30 秒时静默重拉；扫描进行中只轮询 `/api/scan/status` 更新状态文字，不重拉整页。

## 标签 / 保存视图 / 重复文件（2026-11-25）

- **用户标签**：任何条目（文件、笔记、项目、运维记录、企微链接）都能打标签，存在 `entries.user_tags`（JSON 数组），与 `entries.tags`（业务类型标记）**分列**，互不污染。约束：单个 ≤20 字、每条最多 10 个、自动去重。列表最右固定「标签」列显示前两枚 + `+N`；编辑弹窗顶部一次录入（`n-dynamic-tags`）；搜索页搜索框下方有标签栏（带使用次数，点击即过滤），接口也支持 `?tag=` 与关键词组合（`/api/search?q=…&tag=MRP`）。
- **保存视图**：筛选栏左侧「视图」下拉 + 「存为视图」。视图存进 `app_meta.saved_views`，**存的是筛选值而不是结果**，打开时按当时数据重算，不会看到过期内容；按页签归属（运维 / 链接 / 项目各自一套），支持改名与删除，最多 50 个。
- **重复文件**：索引目录页新增卡片，按 `files.sha256` 分组，给出组数 / 冗余文件 / 可释放空间 / 参与比对数；展开的每组列出路径，提供「定位」与「复制路径」。**只报告不删除**——删除权留在用户手上。仅 ≤50 MB 的文件在扫描时计算了哈希，更大的文件不参与比对，`unhashed_files` 里如实计数。
- 三者都不新增表：标签加一列、视图用 `app_meta`、重复文件纯聚合查询。

## 笔记双链 / 凭据动态码 / 快速捕获（2026-11-25）

- **笔记双链**：正文写 `[[页面标题]]` 即渲染为虚线下划线的可点链接。实现是 ProseMirror **Decoration**，**不改文档结构**——`content_json` 里仍是原始方括号文本，导出 Markdown/HTML、参与全文检索、打开老页面都不受影响。编辑器下方显示「本页引用 / 反向链接」两栏：出链按标题匹配页面（找不到标「待建」），反链查其他**非私密页**正文里的 `[[本页标题]]` 并带上下文片段；点任一项按标题查页面并跳转。
- **凭据动态码（TOTP）**：编辑弹窗可填 Base32 密钥，列表「动态码」（标题右侧）显示 6 位码，每 30 秒随列表刷新，点击复制。密钥与密码同样 DPAPI 加密、不进全文索引；**凭据加密导出包含该字段**，换机恢复不丢。算法自实现（RFC 6238，HMAC-SHA1 + 动态截断），无新依赖，已用 RFC 测试向量校验。
- **快速捕获**：全局热键 `Ctrl+Alt+Space` 唤起浮层，记一条运维记录或笔记；`Ctrl+Enter` 保存、`Esc` 关闭。热键由 Win32 后台线程注册（隐藏窗口 + `RegisterHotKey`）；未装 pywin32 / 组合被占用 / `ONLYONE_HOTKEY_OFF=1` 时静默降级，不影响启动。
- **只弹独立小窗**：启动时额外创建一个 **620×272 无边框置顶小窗**（`?capture=1`，默认隐藏），热键只 `show()` 它。**主窗口完全不参与**——不隐藏、不最小化、不还原，它原来什么样，按完热键还是什么样。保存 / 取消后隐藏小窗，焦点还给触发前的窗口。
- **不提供降级形态**：小窗创建或 `show()` 失败时只记日志、不响应热键，**不会**把主窗口缩成卡片（该形态已于 2026-11-26 移除）。`enter_capture` / `exit_capture` 作为工具函数保留，热键与捕获流程都不再调用。
- **主窗口不挂载捕获浮层**：`App.vue` 只在 `?capture=1` 时渲染 `<capture-overlay standalone />`。之前两处都挂，主窗口那份也在轮询 `/api/capture/pending`，热键一按主窗口里也弹一张卡片、必须按 Esc 才消失。捕获期间不触碰主窗口。
- **笔记支持粘贴截图**：笔记模式是 TipTap 编辑器，`Ctrl+V` 直接贴图。图片先以 base64 存在文档里，保存时后端 `persist_inline_images` 落盘到该页附件目录并把 `src` 改写成 `/api/attachments/{note_id}/...`，与记事本里的图片完全一致。
- **笔记落点可指定**：浮层「存到」下拉按笔记本分组选分区，**选一次即记忆**（写进 `app_meta.capture_target`），之后沿用；未设置时回退到第一个笔记本的第一个分区。运维速记固定写成 `category=新需求` 的记录，可在运维页补全。
- **单实例**：启动时用命名互斥量检测，已有 OnlyOne 在跑就把它的窗口置前并退出本进程——两个实例共用一个 SQLite 库、各跑一个 watcher 会重复扫描并抢写锁。调试需要多开时加 `--allow-multi`。
- **热键可换**：`set ONLYONE_HOTKEY=ctrl+alt+k` 可覆盖默认组合（支持 ctrl/alt/shift/win + 字母/数字/F1–F24/space）；注册失败时日志会说明原因，侧栏底部也会显示「热键不可用」。
- **不会白屏**：捕获期间用一层**不透明遮罩**盖住工作台，而不是把工作台 `display:none`——浮层万一没渲染出来，界面仍然可操作，不至于只剩背景色。

## 检索能力

- **字面检索**：FTS5 trigram + 短词 LIKE 兜底。
- **扫描件 OCR**：图片与无文本层 PDF 的内嵌页图走本机离线模板匹配引擎（Pillow + 系统中文字体 + numpy），零云端依赖。**能力边界**：适用于清晰印刷体，对手写 / 艺术字体 / 强噪声效果有限；检测到 tesseract 时自动优先使用。
- **语义检索**：本地确定性稀疏向量（同义词归一 + 字符 n-gram + 余弦），非神经嵌入；结果在「语义相近」独立分组。
- **外部索引插件**：`SearchBackend` 抽象默认关闭；仅当 `ONLYONE_KENSAKU_CLI` 指向真实 CLI 时启用，结果独立分组、不参与跨类型关联。

## 只读预览

- 正文默认 80 行、表格默认 31 行（含表头、表头粘性固定），宽表可「放大查看」到 92vw 弹窗并分批加载；抽屉宽度可拖拽，标题栏可一键最大化。
- **内嵌图片可见**：枚举 `word/media`、`ppt/media`、`xl/media`；缩略图网格收在文末折叠区（默认收起），单击看大图、可上一张/下一张、点击图片在「适应窗口 / 原始尺寸」间切换。
- **原位显示**：正文里的图直接在原文位置渲染——独占一段的居中出大图（≤420px，下方标注「图 N · 宽 × 高」），夹在句子中的出 180px 行内小图，表格单元格里出 160px 小图；点任一张开大图。滚动到才取字节（懒加载）。
- EMF/WMF 矢量图经 Pillow（Windows GDI）栅格化为 PNG，实测流程图文字清晰；`.wdp`/`.svg`/WPS 私有扩展名不可预览，直接不列出。**图片不进全文索引**，图内文字仍需 OCR 才能搜到。原位位置是**段落级近似**（浮动图会被拉到所在段落），且只对 `.docx` 生效。

## 记事本（M7，B 档）

- 三级结构「笔记本 → 分区 → 页面」；TipTap 3 富文本编辑器（粗体 / 斜体 / 标题 / 列表 / 代码块 / 图片 / 表格）。
- **布局**：笔记本下拉 + 分区页签固定在顶部（页签本身不滚动，放不下的收进「⋯」）；左侧是当前分区的页面列表、右侧是编辑器，两栏各自独立滚动，整个页面不再整体滚动。
- **拖拽排序**：分区页签可拖动调整顺序；页面行可在分区内调整顺序，也可直接拖到另一个分区页签上跨分区移动（排序值重排为 1..n 写回 `sort_order`）。新建分区 / 页面默认排到末尾。
- 改动后 1 秒防抖自动保存，带 `revision` 乐观锁；页面级「不参与检索」开关（私密页不进 FTS / 语义 / 全局搜索）。
- **切页签再回来会回到原分区与页面**：`App.vue` 用 `v-if` 切视图，切走即卸载，因此把「笔记本 / 分区 / 页面」三个 id 记在 `stores/viewState.ts`（仅会话内、不落盘），挂载时先回填再让 `loadTree()` 校验有效性；页面被删则只保留分区。深链接 `?note=` 与跨页跳转优先级高于这份记忆。
- **切页签不丢字**：卸载前若仍有未落盘的防抖保存（`saveState === 'dirty'`），先发一次 PUT 再销毁编辑器——`save()` 在第一个 await 之前同步读取 `editor.getJSON()`，所以顺序必须是先 save 后 destroy。
- 公开页面正文自动进入全局检索、语义分组与「关联到项目」；搜索结果里记事本条目带「在记事本中打开」，一键跳到对应页面。
- 图片落盘到 `data/attachments/`，不进 FTS。
- **导入 / 导出 / 备份集中在顶部「更多 ▾」**：导入 `OneNote .mht`（文件 / 文件夹）、导出本页 Markdown、导出本页 HTML + 图片 zip、导出当前分区、导出整个笔记本、备份全库。桌面端导出走**系统另存为对话框**（pywebview 默认禁止下载，原先前端 `<a download>` 点了没有反应），保存后提示完整路径；浏览器模式回退为普通下载。
- **表格**：工具栏「表格」菜单支持插入 3×3、增删行列、合并 / 拆分单元格、删整表、整表行高（紧凑 26px / 标准 36px / 宽松 52px / 自定义）；**列宽可拖拽**（宽度写入 `colwidth` 随文档保存），行高写入表格节点 `rowHeight` 属性。光标不在表内时行列类菜单项置灰。从 Excel / 网页复制可直接 Ctrl+V 粘贴成表格。导出 Markdown 时合并单元格按 GFM 拍平（内容保留、结构丢失，Markdown 无此语义），导出 HTML / zip 则保留 `colspan` / `rowspan`。
- **凭据导出只做 C 方案**：Scrypt + AES-GCM 口令加密，导出文件只含密文；导入时用当前 Windows 账户 DPAPI 重新加密，因此**换机也能恢复**。日常使用仍免主口令，口令只在导出 / 恢复时使用。不做明文导出（与设计方案 §10 冲突）。

## 运维记录的富文本与截图（2026-11-23）

- 字段：发生时间 / **类型** / 系统 / **提出人** / **公司** / 现象 / 根因 / 处置 / 状态 / 耗时 / 归属项目 / 备注。提出人与公司为纯文本、非必填，参与全文检索（`proposer` / `company` 两列随 `init_db` 的 `ALTER TABLE` 自动补给老库）。
- **类型（2026-11-25 增补）**：固定五档下拉 —— BUG / 优化 / 新需求 / 业务方案 / 流程效率，紧跟「发生时间」列。库里直接存中文原值（`incidents.category`，导出与直接查库都可读），老库补列后历史记录为空、界面显示「—」，不做强行回填。选项定义只有 `frontend/src/components/incident-options.ts` 一处，运维记录页与项目工作台内嵌表共用；类型文字同时写入 FTS 正文，全局搜索可搜「流程效率」等。
- **现象 / 根因 / 处置 / 备注**四个字段改成富文本，存 TipTap 的 ProseMirror JSON（与记事本 `content_json` 同一种结构），**不是 HTML**。其余字段仍是纯文本。
- 编辑器不放工具栏，只保留快捷键：`Ctrl+V` 贴图、`Ctrl+B` 加粗、`Ctrl+I` 斜体、`Ctrl+Shift+8` 列表，输入框下方有常驻提示。
- 截图粘贴后前端 >5 MiB 自动压到最长边 2560，后端按内容哈希落 `data/attachments/blob/<sha256前32位>.<ext>`，去重、与记录 id 解耦（新增弹窗里没有 id 也能贴图）。读取走 `GET /api/attachments/blob/<file>`。
- 检索与标题取纯文本：`onlyone.rich.extract_text()` 是唯一实现（记事本也改用它），图片节点不产出字符、JSON 结构不写入 FTS，条目标题形如「SAP-PP · MRP 需求翻倍」。
- 列表「现象」列显示纯文本 + 前缀标记 `〔N 图〕`（放末尾会被列宽省略号吃掉）。
- **老的纯文本记录不做批量迁移**：读取时原样当文本用，用户再次编辑保存时才转成 JSON。
- **列表筛选（前端内存，不改接口）**：关键字全文搜索（跨全部字段，富文本先抽纯文本，空格分词 AND）· 发生时间区间（起、止两个单日期控件，闭区间，可只填一端）· 类型（固定五档下拉，与字段同源）· 公司（下拉，候选值从现有记录去重生成，不引入公司主数据）· 状态 · 项目。筛选后顶部计数显示「筛选后 N / 共 M」，无结果给「没有匹配的记录」空状态，并自动清空勾选；「复制表格（TSV）」导出的是筛选后的行。**筛选条件跨页签保留**：`BizCrud` 的 `filterKey`（运维记录传 `incidents`）把值存进 `stores/viewState.ts`，切走再回来照旧生效；「清除筛选」会同步清掉记忆。
- **双击行即打开编辑**：运维记录 / 企微链接的列表行双击弹出该条编辑弹窗（`BizCrud` 统一实现，操作列里的按钮双击不接管）；项目事项用的是自己的左侧列表，不在此列。
- **超期标黄**：未关闭且距发生时间超过 7 天的行整行浅黄、左侧 3px 警示条（判定口径与概览页一致，见上文「概览页」）；表格上方有常驻图例说明。
- **从全局搜索可直接打开**：运维记录类型的结果行多一个「在运维记录中打开」按钮 → 切到运维记录页签并弹出该条编辑弹窗（现象/根因/处置/图片全在弹窗里）；支持深链接 `?tab=incidents&open=<id>`。

## 从 OneNote 迁移

OneNote 的 `.onepkg` / `.one` 是 MS-ONESTORE 二进制格式，本机 OneNote 的 COM 类型库未注册（`0x8002801D 库没有注册`，Excel/Word 的 COM 正常），所以走 **OneNote 手动导出 `.mht` + 导入** 这条路。

**方式一：界面导入（推荐）**——记事本顶部 **更多 ▾** → 「导入 OneNote .mht 文件（可多选）」或「导入文件夹」。

- 一个 `.mht` = 一个分区，分区名取文件名；导入到**当前选中的笔记本**
- 逐个文件串行上传，显示 `正在导入 2/5：MM.MHT`；完成后弹窗汇总分区 / 页面 / 图片数
- 重复导入同一节自动生成「MM (2)」，不会把页面混进旧分区
- 单文件上限 64 MB，单次最多 20 个文件

**方式二：命令行**（默认只分析、不写库）：

```powershell
py -3 tools\import_mht_notes.py --input "D:\1118\MM.MHT"                  # 单节，只看报告
py -3 tools\import_mht_notes.py --input "D:\1118\SAP\" --write --book "SAP 笔记"   # 整本目录
```

OneNote 端的操作：**文件 → 导出 → 范围选「节」或「笔记本」→ 格式「单个文件网页 (.mht)」**。

映射：**笔记本 → OnlyOne 笔记本**，**每个 `.mht` → 一个分区**，**节内每页 → 一个页面**。

保真度：页面标题、正文段落、表格（含 colspan/rowspan）、图片（压缩 + 哈希落盘，位置保留）、粗体/斜体、列表都保留；**子页面缩进、手写墨迹、内嵌非图片附件丢失**，`onenote:#...` 站内链接降级为纯文字。**整本导出为单个 .mht 时节边界不存在**（实测 177 页页间标记完全一致），整本只能进一个分区。
