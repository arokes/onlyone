# 概览页（Home）设计方案 — 功能 1 + 功能 3

日期：2026-11-25　状态：**①②③④ 全部完成**（接口 21/21、概览界面 10/10、筛选回归 21/21、打包版实测通过）；未做的验证缺口已登记为 `docs/续接-未完成项.md` 的 G-21 / G-22
范围：① 新增「概览」页作为默认落地页；② 未关闭运维的超期提醒（概览页计数 + 运维表标黄）
不涉及：新表、新依赖、新前端库；不动编辑器与索引链路

---

## 0. 结论与三个取舍

| 取舍 | 决定 | 理由 |
|---|---|---|
| 默认页 | 无 `?tab=` 深链接时落在 `home`，其余行为不变 | 现状默认 `search` 是空搜索框，每天第一屏没有信息量；深链接与 `Ctrl+K` 逻辑保持原样 |
| 聚合方式 | **一个接口 `GET /api/overview` 一次取全** | 概览页 6 个区块若各开接口，首屏 6 次往返；单连接 6 条 SQL 实测应在 20ms 量级 |
| 超期判定 | 按 `occurred_at` 计时，默认 7 天，**不加数据库列** | 「这个问题挂了多久」比「多久没动」更贴直觉；不物化状态就不会有回填与一致性问题 |

一个刻意的边界：**概览页只读**。所有点击都跳转到对应页签去处理，不在概览页内直接改数据（避免出现第二套编辑入口）。

## 1. 接口

### 1.1 签名

```
GET /api/overview?days=7&limit=8
```

| 参数 | 类型 | 默认 | 约束 | 说明 |
|---|---|---|---|---|
| `days` | int | 7 | 1–365 | 超过该天数仍未关闭即视为超期 |
| `limit` | int | 8 | 1–20 | `recent_files` / `recent_notes` 的条数 |

鉴权由现有 token 中间件统一覆盖（`/api/*` 都要 `X-OnlyOne-Token`），无需额外处理。

### 1.2 返回结构（真实字段名）

```json
{
  "generated_at": "2026-11-25 10:45:12",
  "params": { "days": 7, "limit": 8 },
  "counts": {
    "roots": 2, "files": 1367, "entries": 1234, "notes": 42,
    "projects": 5, "links": 18,
    "incidents_open": 3, "incidents_overdue": 1, "failures": 2
  },
  "recent_files": [
    {
      "entry_id": 812, "title": "MRP 需求对比 20261124.xlsx",
      "rel_path": "SAP\\MRP\\MRP 需求对比 20261124.xlsx",
      "ext": "xlsx", "size": 184320,
      "mtime": "2026-11-24 18:22:10", "root_kind": "local"
    }
  ],
  "open_incidents": [
    {
      "id": 7, "title": "SAP-PP · MRP 需求翻倍",
      "system": "SAP-PP", "category": "BUG",
      "occurred_at": "2026-11-13 09:00",
      "days_open": 12, "overdue": true, "symptom": "MRP 需求较昨日翻倍…"
    }
  ],
  "recent_notes": [
    { "id": 31, "title": "MRP 边际码排查", "section": "SAP 笔记",
      "updated_at": "2026-11-24 15:01:33" }
  ],
  "storage": {
    "db_mb": 108.1, "free_mb": 16.4, "free_ratio": 0.132,
    "backup_at": "2026-11-17 09:12:00", "backup_days_ago": 8
  },
  "scan": { "phase": "idle", "percent": 100.0, "last_event_at": "2026-11-25 09:58:02" },
  "warnings": []
}
```

约定：
- `warnings` 是字符串数组。**任何单个区块查询失败，只把该区块填空数组/`null` 并追加一条 warning，整体仍返回 200**——概览页不能因为某个模块出问题而整页报错。
- `entry_id` 可能为 `null`（文件已从磁盘消失但索引行还在），前端点击时按 `null` 禁用。
- `days_open` 解析失败（`occurred_at` 格式异常）时返回 `null`，且不参与超期计数。

### 1.3 SQL（逐块，可直接抄）

**计数：一条 SQL 用子查询，避免 7 次往返**

> 实现补充：`incidents_open` 放在这条 SQL 里（只依赖 `status` 列），即使 `open_incidents`
> 明细查询降级，概览上的「未关闭 N 条」仍是真实值；`incidents_overdue` 依赖天数阈值，
> 由 `_open_incidents()` 在 Python 侧计算后回填，保证「列表里看到的超期」与「计数」同一口径。

```sql
SELECT
  (SELECT count(*) FROM roots)                              AS roots,
  (SELECT count(*) FROM files)                              AS files,
  (SELECT count(*) FROM entries)                            AS entries,
  (SELECT count(*) FROM notes)                              AS notes,
  (SELECT count(*) FROM projects)                           AS projects,
  (SELECT count(*) FROM links)                              AS links,
  (SELECT count(*) FROM incidents WHERE status='open')       AS incidents_open,
  (SELECT count(*) FROM extract_failures WHERE attempts>=3)  AS failures;
```

**最近改动文件**（`files.mtime` 是 REAL，epoch 秒，转本地时间由后端做，前端不再算时区）

```sql
SELECT f.rel_path, f.ext, f.size, f.mtime,
       e.id AS entry_id, e.title, r.kind AS root_kind
FROM files f
LEFT JOIN entries e ON e.type='file' AND e.ref_id=f.id
LEFT JOIN roots  r ON r.id = f.root_id
ORDER BY f.mtime DESC
LIMIT ?;
```

**待跟进运维**（富文本 `symptom` 必须走 `rich.extract_text`，否则 JSON 结构会漏到界面）

```sql
SELECT id, occurred_at, system, category, status, symptom
FROM incidents
WHERE status='open'
ORDER BY occurred_at ASC
LIMIT 50;
```

后端逐行补 `days_open` / `overdue`：

```python
now = datetime.now()
for row in rows:
    try:
        days = (now - datetime.strptime(row["occurred_at"][:16], "%Y-%m-%d %H:%M")).days
    except (TypeError, ValueError):
        days = None
    row["days_open"] = days
    row["overdue"] = days is not None and days > days_param
```

> 解析用 `[:16]` 截断，兼容库里两种历史写法（`YYYY-MM-DD HH:MM` 与带秒的 `YYYY-MM-DD HH:MM:SS`）。

**最近笔记**（私密页不进概览，与检索口径一致）

```sql
SELECT n.id, n.title, s.name AS section, n.updated_at
FROM notes n
JOIN sections s ON s.id = n.section_id
WHERE n.is_private = 0
ORDER BY n.updated_at DESC
LIMIT ?;
```

**体积与备份**：直接复用 `maintenance.stats()`（已返回 `file_mb` / `free_mb` / `free_ratio`）；
备份时间取 `DATA_DIR / "backups"` 下文件名匹配 `onlyone-*.db` 的最大 `mtime`，没有则 `backup_at=null`。

**扫描/监听状态**：`scanner.progress_snapshot()` 取 `phase` / `percent`；`watcher.status()` 取 `last_event_at`。
两者都是内存态，概览接口顺带返回，前端不需要再打两个接口。

### 1.4 性能（已用真实库实测，2026-11-25）

真实库副本：`files` 1361 行、库文件 113 MB。

| 查询 | 加索引前 | 优化后 | 手段 |
|---|---|---|---|
| `_counts` | 17.8 ms | 23.4 ms（冷）/ 0.7 ms（热） | — |
| `_recent_files` | **232.8 ms** | **3.9 ms** | 新增 `idx_files_mtime` |
| `_open_incidents` | — | 0.3 ms | 表小，无需索引 |
| `_recent_notes` | — | 0.5 ms | — |
| `_storage` | **166.6 ms** | **1.5 ms** | `maintenance.stats(include_counts=False)` 跳过 fts 大表统计 |

合计约 **34 ms**（首次含冷启动 IO；预热后 <10 ms），满足首屏要求。

两处顺带改动都已写进代码与回归：

1. `db.py` 的 SCHEMA 增加 `CREATE INDEX IF NOT EXISTS idx_files_mtime ON files(mtime);`。
   `init_db()` 每次执行 SCHEMA，老库启动即自动补索引，无需单独迁移脚本。
2. `maintenance.stats()` 增加关键字参数 `include_counts: bool = True`；默认行为不变（`RootsView` 照旧拿全量指标），概览传 `False`。
   不重复实现体积口径，避免两套 `file_mb`。

不做缓存：概览必须反映刚保存的数据，缓存收益不值一致性风险。

## 2. 功能 3：未关闭运维超期提醒

### 2.1 规则

| 项 | 值 |
|---|---|
| 超期条件 | `status='open'` 且 `occurred_at` 距今天数 > 阈值 |
| 阈值 | 默认 **7 天**；接口 `days` 参数可覆盖，前端常量 `INCIDENT_OVERDUE_DAYS = 7` 作为默认值 |
| 不计入 | `status='closed'`、`occurred_at` 为空或解析失败 |
| 边界 | 恰好 7 天不算超期（用 `>` 而非 `>=`），避免"当天创建第二天就红"的噪音 |

### 2.2 两个落点

**落点一：概览页「待跟进运维」卡片**
每行显示：`标题 · 类型 · 挂起 N 天`，超期的行加左侧 3px 警示条 + 天数用警示色；非超期只显示天数（弱化）。点击整行 → `jump.jumpToIncident(id)`，跳运维页并直接打开该条编辑弹窗（该动作已存在，零新增代码）。

**落点二：运维记录表格标黄**
`BizCrud` 新增一个可选 prop：

```ts
// frontend/src/components/BizCrud.vue
props: { ..., rowClass?: (row: Record<string, any>) => string }
```

```ts
function rowProps(row: Record<string, any>) {
  return { class: props.rowClass?.(row) || '', onDblclick: ... }
}
```

`IncidentsView.vue` 传入判定函数（纯前端，不改接口、不写库）：

```ts
const OVERDUE_DAYS = 7
function daysOpen(row: any): number | null {
  const raw = String(row.occurred_at || '').slice(0, 16)
  const t = Date.parse(raw.replace(' ', 'T'))
  if (Number.isNaN(t)) return null
  return Math.floor((Date.now() - t) / 86400000)
}
const rowClass = (row: any) =>
  row.status === 'open' && (daysOpen(row) ?? 0) > OVERDUE_DAYS ? 'row-overdue' : ''
```

样式（`styles.css`，新增两个警示令牌，不写死 hex）：

```css
:root {
  --warn: #8a6420;        /* 警示文字，暖纸 4.88:1 过 AA */
  --warn-soft: #fbf2e4;   /* 超期行底色 */
}
tr.row-overdue > td { background: var(--warn-soft); }
tr.row-overdue:hover > td { background: var(--warn-soft); }
tr.row-overdue > td:first-child { box-shadow: inset 3px 0 0 var(--warn); }
```

> 实现补充：判定函数落在 `frontend/src/components/incident-options.ts`
> （`incidentDaysOpen` / `incidentRowClass` / `INCIDENT_OVERDUE_DAYS`），
> **项目工作台内嵌的运维表也传同一个 `:row-class`**，否则同一记录在两处一个标黄一个不标。
> 前端严格校验日期（回读年月日，拒绝浏览器自动滚动的 `02-31`），与后端 `days_open=null` 口径一致。

### 2.3 为什么不做"已催办"标记

会引入第三个状态（open / nudged / closed）和一个新列。当前运维记录量级（个位数到几十条）用"看得到就是提醒"已足够；等真的出现"同一条被提醒十次"再讨论，避免提前复杂化。

| 区块 | 取数 | 点击行为 | 空态文案 |

| 统计条 5 格 | `counts.files` / `entries` / `incidents_open` / `incidents_overdue` / `failures` | 后三格跳对应页（失败 → roots 页失败清单） | — |
| 最近改动 | `recent_files` | `jump.jumpToEntry(entry_id, 文件名去扩展名)` → 搜索页自动以它检索并同时打开预览；关掉预览后停在结果列表。`entry_id` 为空则提示并禁用 | 「还没有索引到文件，去添加索引目录」+ 按钮 |

| 系统状态 | `storage` + `scan` | 备份超 7 天显示「建议备份」，点击调 `/api/backup`（二次确认） | — |

### 3.4 刷新策略

- 挂载时拉一次；点「刷新」重拉。
- 窗口重新获得焦点（`visibilitychange` → visible）时静默重拉，但**距上次 <30 秒不重拉**，避免频繁切窗口打库。
- 当 `scan.phase === 'scanning'` 时，每 2 秒轮询一次 `/api/scan/status` 只更新顶部状态条，**不重拉整个 overview**。

## 5. 验收

### 5.1 接口（`tools/verify_overview.py`，独立临时数据目录）

1. 空库：`counts` 全 0、`recent_files` 为空、`warnings` 为空、HTTP 200。
2. 造 3 条文件 + 2 条运维（一条 12 天前未关闭、一条今天已关闭）+ 1 条笔记，断言：
   - `counts.files == 3`、`incidents_open == 1`、`incidents_overdue == 1`
   - `recent_files` 按 `mtime` 倒序，第一条是最新文件
   - `open_incidents[0].days_open == 12` 且 `overdue == true`
   - 已关闭那条不出现在 `open_incidents`
3. `?days=30` 时同一条记录 `overdue == false`（阈值生效）。
4. `occurred_at` 传 `"2026-13-99"` 构造脏数据：`days_open == null`，不 500。
5. `?limit=1` 时 `recent_files` 长度 1；`?limit=999` 被夹到 20。

### 5.2 界面（Chrome headless + DOM 断言）

- 打开 `/?token=...`（不带 `tab`）落在概览页，`document.body.innerText` 含「概览」「待跟进运维」。
- 概览页出现 `1` 条超期运维，文案含「挂起」与天数。
- 切到运维记录页，超期行元素带 `row-overdue` class。
- `?tab=search` 深链接仍落在搜索页（防回归）。
- 截图存 `docs/screenshots/24-overview.png`。

| 默认页从搜索变概览，用户想直接搜 | 多一次点击 | `Ctrl+K` 仍直达搜索；概览顶部提供搜索框入口（可选，第二批） |
| `files` 表很大时 `ORDER BY mtime` 变慢 | 首屏卡顿 | 先实测；超 100ms 加 `idx_files_mtime`，不改接口 |
| 概览页聚合逻辑分散在 SQL 与 Python | 后续难维护 | 所有超期判定集中在 `overview.py` 一处；前端只用返回值，不重算 |
| 标黄与选中态视觉冲突 | 视觉噪音 | 用"行底浅色 + 左侧 3px 条"，避免整行高饱和填充 |
| 用户不想要默认页变更 | 体验被改 | 只需回退 `jump.ts` 一行，其余功能不受影响 |
