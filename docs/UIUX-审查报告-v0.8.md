# OnlyOne v0.8 · UI/UX 审查报告

> 审查对象：`frontend/`（Vue 3 + naive-ui 2.42），暖纸主题 v0.8
> 方法：源码令牌审计 + 真实运行截图（本地后端 + 8 个页签逐页截取）+ WCAG 对比度实测
> 结论期限：本次仅出分析与改法，未改动任何代码

---

## 一、结论

1. **底色不难看，问题在"没有层级"。** 卡片与背景 1.08:1、内嵌层 1.10:1、描边 1.35:1 —— 整页是一层米色，所有结构靠一条几乎看不见的描边撑着。这是"看着发糊、找不到重点"的真实原因，不是橙色选错了。
2. **第二根因是强调色分裂。** 品牌与导航用陶土橙、主按钮用深墨蓝、搜索结果与图标底用雾蓝、`warningColor` 又单独内联了一个 `#b0512c`。一屏最多三种"强调"同时出现，搜索页最严重：一屏 8 条结果 ≈ 40 处淡蓝填充，等于没有高亮。
3. **可调，而且性价比很高。** 改 6 个令牌 + 3 条使用规则 + 1 个统一空状态组件，能拿走约 80% 的观感收益；**不建议动布局骨架**（208px 左导航 + 内容区这个结构是对的，8 个页签也没必要合并）。

## 三、P0：只改令牌 / 只改一处就能见效

### P0-1　把表面拉开，别靠描边
| 变量 | 现值 | 建议值 | 依据 |
|---|---|---|---|
| `--paper` | `#f8f4ec` | `#f4eee2` | 底压下去一档，卡片才能浮起来（overlay 1.05→1.14） |
| `--line` | `#e5dbcd` | `#d9cbb5` | 描边 1.35→1.57，边界不用加粗就看得见 |
| `--line-soft` | `#efe7da` | `#e8ddcb` | 行分隔 1.21→1.32 |
| 表头底色 | `#f1e9dc`（=paper-2） | `#ece2d3`（=paper-3） | 现在表头只比卡片深 1.10，读不出是表头 |

⚠️ **改底色必须连带核对比度**：`--paper-3 #ece2d3` 上 `ink-3 #6f675b` 只有 **4.35:1（不达 AA）**。所以 `--paper-3` 只允许承载正文级深色（`--ink` 12.21、`--ink-2` 5.67），**11–12px 辅助文字不要落在 paper-3 上**；统计块 `stat-tile` 建议从 paper-2 改成 `--surface`，顺带解决 `--success` 在 paper-2 上只有 4.40 的问题（surface 上 5.22）。

⚠️ **表头色有三个来源，必须同批改**：`App.vue:79 tableHeaderColor`、`NotesView.vue:1109`、`SearchView.vue:902` 各写了一遍 `paper-2`。只改其中一处，会出现"三张表三种表头"。

### P0-2　给强调色定分工，不许再自由发挥
| 角色 | 用哪个 | 允许出现在 | 明令禁止 |
|---|---|---|---|
| 主操作（实心按钮） | `--night #1f3040` | 一屏最多 1 个：搜索、保存、新增 | 拿它做装饰、做链接 |
| 品牌 / 当前定位 / 命中 | `--accent #bf5a36` + `--accent-strong #a44524` | logo、当前导航项、`mark` 底色、2px 指示条 | **`--accent` 对底 3.84，禁止当正文**；正文一律 `--accent-strong`（5.26 达标） |
| 信息（链接 / 徽章 / 小图标底） | `--info #3e6288` / `--info-deep` / `--info-soft` | 文字、≤24px 的图标底、状态标签 | **禁止整条区域填充**（见 P0-3） |
| 语义 | success / danger / warn | 状态点、结果数字 | 顺手内联一个 `#b0512c`（App.vue:62），统一到 `#8a6420`（4.88 达标） |

一句话规则：**墨蓝只做"按下去会发生什么"，橙色只做"你在哪里"，蓝色只做"这是个附加信息"。**

### P0-3　搜索页：一屏 40 处蓝底 = 没有高亮
`SearchView.vue:853` 把每条结果的标题做成 `info-soft` 实底条，`:875` 又把 4 个图标按钮做成同色方块。一屏 8 条 = 8 条标题带 + 32 个蓝方块，和命中词 `mark`（橙底）打架。

改法：标题条去掉填充，用 `--surface` + 500 字重 + 14px；蓝色只留在"标题命中"这个 11px 徽章上。区分三种状态：
- 命中 = `mark` 橙底（唯一的高亮）；
- 悬停 = `--paper-2` 行底；
- 选中 = 左侧 2px 橙条（与左导航同一语言）。

### P0-4　空状态要能干活
现状 5 个页面首屏是空的（无项目 / 无笔记 / 无凭据 / 无数据），naive 默认插画是冷灰线性图，落在暖纸上突兀，且**没有任何按钮**；表格 0 行还挂着 `1 2 >` 分页器（`BizCrud.vue:322`）。

改法：抽一个 `EmptyState` 组件（图标 48px、`--ink-3`、标题 14px/`--ink`、说明 12px/`--ink-2`、一个主按钮），插到 `n-data-table` 的 `#empty`；`pageSize` 保持 10 但 `v-if="rows.length"` 时才渲染分页。

### 附：侧栏 72px 折叠态规格（P1-9 的必要补充）

不能只隐藏文字，否则 8 个图标会挤成一条不可区分的竖线、8 个可点击目标小于 44px。

| 项 | 值 |
|---|---|
| 图标 | 20px（现在 16px），`--ink-2`；激活态 `--accent-strong` + 2px 橙竖条 |
| 项高 | 36px（`padding: 7px 0` + `justify-content: center`，满足点击目标） |
| 组标签 | 收成 1px 分隔线 + 上下 6px 间距，不保留文字 |
| 品牌 | 只留一个 12px 字样「O」或单色 mark，去掉副标题 |
| 底部 | 只留状态点（`--success`），版本号与「本地运行」文案隐藏 |
| 实现 | 用 `SideNav` 的 `compact` prop + `:deep` 覆盖，**别写裸露的 `.sidebar` 全局选择器**，否则会和 `App.vue` 的 flex 布局打架 |

折叠态必补三件语义（现在都没有，三者缺一不可）：
- `aria-label` **常显**（不是折叠时才有）—— 它是无障碍名，展开态有可见文字时加了也无害，这样代码里不用分叉；
- `title` **仅折叠时** 加 —— 给鼠标用户的视觉提示，展开态加了会重复；
- 图标 `<svg aria-hidden="true" focusable="false">` —— 否则部分读屏会把 path 当内容念。
底层必须改成 `padding: 7px 0` + `justify-content: center`（现在 `padding: 7px 9px` 靠 flex 起点对齐，文字一没，图标就偏左，不会自动居中）。
可选 1 行：底部只留状态点时给圆点挂 `:title="'本地运行 · ' + version"`，版本号不至于彻底消失。

## 五、P2：可延后，但记一笔

- 2 处硬编码色：`SearchView.vue:958 #fff`、`RootsView.vue:461 #fdf7f1`（后者还是个没进令牌的第 4 种暖白）。
- `var(--radius-sm, 8px)`（RootsView.vue:460）里的 fallback 与真值 6px 不一致，是令牌漂移的活证据。
- 颜色语义缺位：凭据库没有"可用 / 失效"、项目没有"归档"的视觉状态，只能靠文字读。
- 快捷键只有 Ctrl+K；搜索结果的上下选择 / 回车打开 / Esc 关抽屉都没有键盘路径。
- 间距是 3/4/5/6/7/8/9/10/12/14 的散值，建议锁 4px 栅格（4/8/12/16/24）。
- 动效：naive 默认 + 自己写的 hover 混用，未统一时长。
- **粘贴图无 alt（WCAG 1.1.1 不通过，且是可见的产品缺陷）**：`NotesView.vue:652` 只传 `{ src }`。三个后果：读屏完全不可读；图内容不进检索；**「导出本页 MD」会把每张图导成 `![](url)`，文件名彻底丢失** —— 粘 10 张截图导出后就是 10 个无法区分的空链接（Tiptap 3 的 Image 扩展按 `![alt](src)` 渲染 Markdown），而导出按钮就摆在记事本底部，是这工具的正式出口。改：`attrs: { src, alt: target.name }`（文件名第 630 行就在手上），**1 行**。所以这条从"合规项"改标为**产品项 + 合规项**。
  - 注意 `alt = target.name` 只是地板（读屏听到 `image (3).png`），真正解法是"选中图后可编辑替代文本"，属产品功能，单独立项，别顺手扩成属性面板。
- **宽图被压在 720px 正文列里**：`MAX_EDGE = 2560`（NotesView.vue:24），粘贴截图最长边可达 2560，而内容区最宽 1440 —— **"图比正文列宽"是常态不是特例**。建议"仅图片出血"到栏宽：**替换** `NotesView.vue:1090`，写成一对规则 —— `.tiptap :deep(.tiptap-body) > :not(img) { max-width:720px; margin-inline:auto }` + `.tiptap :deep(.tiptap-body) > img { display:block; margin-inline:auto; max-width:100%; height:auto }`。别写成 `.tiptap img`（会把行内小图压成块级断行）。
  - `height:auto` 不是可选：`max-width` 属 CSS，盖不住 `<img height="800">` 这种 presentational hint，缺它就会出现"宽缩了、高没缩"的压扁变形。**影响的是 `.mht` 导入与备份恢复 / 外部写入的 content_json**（粘贴路径不进 `width/height`，别把这条写成"修复网页粘贴"，现场复现不出来）。
- **版心上限只在 ≥1114px 生效**：1440 窗口下正文列 910，1280 下 750，1024 下 630 —— 也就说 1024 档根本触发不到 720 上限，`max-width` 只是"宽屏兜底"。验收时把窗口拖到 1280 看一次，确认正文不跳变。
  - 术语分开：**1114 = 物理阈值**（窗口要宽到多少，正文列才真的顶到 720），**1280 = 主动断点**（我们自己选的、开始收内容区的那一档）。两者别混写成一个数。
- `enqueueImage` 回写 Tiptap 时没透传 `width` / `height`（NotesView.vue:641–649）：只有 `src` + `data-origin`，ProseMirror 重排后滚动位置会漂。补 `naturalWidth/naturalHeight` 约 8 行。**这属于缺陷修复不属于 UI 优化，单独立项，别混进来。**

## 六、明确不建议改（现状是对的）

- 左侧 208px 纵向导航 + 三组分组：比顶部横向页签更适合 8 个入口，别回退。
- 13px 的**工具型密度**（表格、列表、侧栏、工具栏）：这是工作台不是文档站，别为了"呼吸感"整体拉到 15px。唯一例外是记事本的长文阅读面（P1-1b 单独放大）。
- 暖纸底色方向本身：它和"本地、离线、个人"的产品气质是一致的，问题在明度关系，不在色相。
- 令牌集中管理 + 视图层只引用变量：这条纪律要守住，新增颜色一律先加令牌。
- 删除走二次确认：保留。
