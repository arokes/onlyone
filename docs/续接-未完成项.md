### 2.6 M6 能力边界（保留）

1. OCR 是**离线模板匹配**（Pillow + 系统中文字体 + numpy），非通用神经 OCR；适用清晰印刷体。原因：Python 3.14 无 onnxruntime/torch 轮子，Windows 内置 WinRT OCR 的异步桥接被环境安全策略拦截，按规则未绕过。检测到 tesseract 自动优先。
2. 扫描 PDF 用 pypdf 取 `page.images` 字节流走 OCR，无需渲染库；纯矢量扫描件仍标失败。
3. 语义检索是**本地确定性稀疏向量**（11 组同义词 + 字符 n-gram + 余弦），非神经嵌入；替换 `semantic.embed()` 可升级。
4. 三组结果独立分组、不混排。

### 2.9 M7 能力边界与风险（重要）

1. **笔记进 FTS 是明文索引**（FTS5 表无加密），`data/onlyone.db` 被拷走即读到全部公开笔记；同一 Windows 账户下的其他进程也可读。FTS5 删行不擦页、WAL 保留历史版本，自动保存越频繁磁盘明文残留越多 —— 已用「2 万字截断入索引 + 保存后 `wal_checkpoint(TRUNCATE)`」缓解，但**未消除**。用户已明确接受此本地场景风险。
2. **私密页开关**是护栏：`is_private=1` 不建 `entries` 行，因此不进 FTS / 语义 / 全局搜索；但仍以明文存 `notes.content_json`，不是加密存储。
3. **凭据导出只做 C**：导出文件只含密文，口令丢失不可恢复；不做 A（DPAPI 密文原样，换机不可恢复）与 B（明文，违反 §10）。全库备份会包含凭据 DPAPI 密文，同样**换机不可直接解密**，跨机请用凭据加密导出。
4. **图片附件**落 `data/attachments/<note_id>/`，文件名为内容 SHA-256 前 32 位（同页去重），不进 FTS；导出时重写为 zip 内相对路径，导出文件不含一次性令牌。附件读取路径对令牌放行（本地随机端口 + 其余 API 仍受保护）。
5. **TipTap 富文本**的 `content_json` 由前端生成，后端只抽文本与做导出白名单渲染（转义 + 仅允许本地附件路径），不执行任何 HTML；编辑器本身不 `v-html`。
6. **导出文件名用 ASCII**（HTTP 头只能 latin-1），中文标题保留在导出内容里 —— 本轮修过一次 500。
7. 富文本目前支持粗体/斜体/标题/列表/代码块/图片；**未做**自由画布定位、手写墨迹、页面双向链接、云端同步（与单机离线约束冲突）。图片粘贴的完整能力与边界见 §2.16。

**能力边界（如实记录）**：

1. 外链图只在浏览器 `fetch` 成功（同源 / 允许 CORS）时转存；失败即忽略并 toast 提示，**不引入后端代理下载**，因此无 SSRF 面。`file://` 图浏览器不提供字节，直接忽略。

4. **去重仅限同一 `note_id` 目录**。跨页复用会让删 A 页时的 `rmtree` 删掉 B 页正在引用的文件；要做跨页去重必须改全局附件目录 + 引用计数，未做。
5. 历史 `uuid` 命名的旧附件仍可正常读取，只是不参与新去重。
6. 批量粘贴的多图紧邻排列；图文混排的默认粘贴会替换当前选区（编辑器正常语义，非缺陷）。
7. 前端压缩依赖 `createImageBitmap` / canvas；WebView2 若不支持则退回原图，由后端 10 MiB 兜底。
8. `verify_note_paste.mjs` 依赖本机 Chrome 与 `frontend/dist`，运行前必须 `npm run build`；它验证的是合成 ClipboardEvent，不等于所有真实应用（Word / 微信）的剪贴板格式覆盖。

### 2.18 启动入口退出路径修复（2026-11-16）

**问题**：PowerShell 执行 `py -3 .\run.py`，关闭桌面窗口后进程不退出，只能强关 Shell。

**根因**（`backend/run.py`）：

1. `webview.start()` 返回后 `main()` 直接结束，但 `server.should_exit` 只在 `except KeyboardInterrupt` 分支设置，**正常关窗从不通知 uvicorn 停机**；
2. `server.install_signal_handlers = lambda: None` 禁用了 uvicorn 信号处理器，主线程又在 GUI 消息循环里，Ctrl+C 不可靠；
3. `--browser` / WebView2 降级路径的 `worker.join()` 是无限等待，关浏览器窗口必然挂死；
4. pywebview 6.2.1 的 Windows winforms/Edge 后端留下非守护线程或 CLR/COM 引用，解释器无法自行退出。

**改动**：`window.events.closing` 回调立即设 `should_exit` 并启动 8 秒 daemon 看门狗；窗口启动段包 `try/finally`，统一 `server.should_exit = True` + `worker.join(timeout=5)` + flush 日志 + `os._exit(0)`；`KeyboardInterrupt` 走同一收尾；`--browser` 打印「关闭窗口后请按 Ctrl+C 退出」提示。docstring 补充三种模式的退出方式。

**验证**：mock `webview.start()` 模拟关窗 → 约 1.5 秒退出、日志有「OnlyOne 已退出」、测试端口释放；`--browser` 路径用 SIGINT 模拟 Ctrl+C → 退出码 0、日志有「收到中断，正在退出」；回归 `verify_notes` 21/21、`verify_note_ui` 11/11 未受影响。

**边界**：关窗验证用的是 mock 回调，不是真实 WebView2 窗口（G-1 仍未验证）；浏览器模式关窗口本身不会退出，仍须 Ctrl+C（已在控制台提示）。

### 2.19 索引库体积维护（2026-11-17）

**背景**：v0.9 引入 docx 内嵌 Excel 抽取后，`7-11计划策略…docx` 正文从 1003 字涨到 133443 字，用户质疑「大文件索引对库存储的影响」。实测（临时副本上做 A/B，不动生产库）：

| 项 | 体量 | 相对正文 |
|---|---|---|
| 正文 1367 条 | 26.3 MB | 1.0x |
| FTS5 trigram 索引 | ~73 MB | 2.8x |
| `semantic_index` 稀疏向量（JSON） | 33.4 MB | 1.3x |
| 有效数据合计 | **108.1 MB** | **4.1x** |
| `data/onlyone.db` 实际 | **309.1 MB** | 3.8x 膨胀 |

单文档净占 1.12 MB（133443 字、262.8 KB UTF-8）。133443 字**不是重复**：4663 行 / 唯一 3738 行（重复率 19.8%，均为「非反冲」「材料」这类字段名），中文 48%，是 16 张工作表真实内容。

**垃圾来源**：① freelist 32323 页 = 126.3 MB（条目更新都是 DELETE+INSERT，页不归还）；② FTS5 死段 74.6 MB（`DELETE` 只写 tombstone）。

**实现**：

- `backend/onlyone/maintenance.py`：`compact()` = `INSERT INTO fts_entries(fts_entries) VALUES('optimize')` → `VACUUM` → `wal_checkpoint(TRUNCATE)`；先查磁盘余量（需 ≈库大小），失败只返回原因不抛。
- `tools/db_maintenance.py`：离线 CLI（`--dry-run` / `--no-vacuum` / `--db`）。
- 自动维护：`scanner._job_main` 结束时**另起守护线程**（`onlyone-compact`）调用 `auto_compact_if_needed()`，门槛为空闲页 ≥16 MB 且距上次 ≥1 小时，写 `app_meta.last_compact_at`；`guard` 在 VACUUM 前二次确认无扫描在跑。
- 阈值可配：`ONLYONE_COMPACT_MIN_FREE_PAGES`（默认 4000 页）、`ONLYONE_COMPACT_MIN_INTERVAL_SEC`（默认 3600，0=每次都做）。

**结果**：`309.1 MB → 108.1 MB`（-65%，6.0s）；`integrity_check=ok`、FTS `integrity-check` 通过、条目数 1367 与检索结果不变。自动维护实测 `109.8 → 108.9 MB`（4.3s）。

**坑（重要）**：

1. 维护**不能**挂在扫描线程的 `finally` 里跑：`_JOBS[root]` 是否存活就是「该目录正在扫描」的判定，扫描线程多活几秒会让紧随其后的 `rebuild` 吃 409。必须先 `_JOBS.pop()`，再起独立线程。
2. `optimize` 必须做，`DELETE FROM fts_entries` 不回收索引段（清空全表只释放 17.4 MB，`DROP TABLE` 才释放 147.9 MB）。
3. `VACUUM` 不能在事务内执行；`fts_entries` 是普通 fts5（非 external content），删行主键是 rowid，`entry_id` 为 UNINDEXED 列。

**边界**：语义向量仍是 JSON 文本（33.4 MB，占 31%），未做瘦身；要再降需改 `semantic.embed()` 的 top-N 截断，会牺牲一点召回，尚未实施。

### 2.21 只读预览显示文档内嵌图片（2026-11-17）

#### ⚠ 2026-11-17 18:35 结论：`-system=` 必须传系统标识（SID）

> **本条结论正确**，2026-11-18 的 `sapshlib` trace 再次确认。当天下午曾一度误改为
> 传连接项名，当天 15:34 已改回，完整证据与认知轨迹见 §2.27。

第一轮（15:23）结论「加 `-type=System` + 连接项名」和第二轮（18:20）结论「去掉 `-type=System`、
仍用连接项名」**都是错的** —— 用户两次都报同一个错。真正原因由 SAP GUI 自己的 trace 坐实。

**决定性证据**：`%LOCALAPPDATA%\SAP\SAP GUI\Traces\sapshlib_<pid>.trc`
（传 `DS4-120ZH` 时）：

```
Command: ' /SHORTCUT=" -system=DS4-120ZH -client=120 -user=10000265 -language=ZH "'
Getting Description according to System ID in SAP landscape file >DS4-120ZH<
Error getting system data:
SAP GUI 快捷方式的部分数据不可用：系统描述和 GUI 启动参数未知，输入缺失的数据。
Error in LoadAll: code = 516, Not all system data are available
```

sapshlib 把 `-system=` 的值当 **System ID** 去查，`DS4-120ZH` 不是 System ID（它只是 XML 快捷方式
工作区里的条目名），查不到就退化成要求手填的属性框。这就是「部分数据不可用」的全部来源。

**实机对照**（每组单发、跑前清空 `sapgui.exe` 与登录框）：

| 参数 | 结果 |
|---|---|
| `-system=DS4-120ZH`（前两轮的做法，含/不含 `-type` 都一样） | exit 0，**trace 报 516**，弹「SAP 快捷方式属性」 |
| `-system=DS4 -client=120` | **2.5s 弹出「SAP GUI 快捷方式 - 登录 (DS4, 120, ZH, )」，用户名已填** |
| `-system=QS4 -client=100` | 1.7s 弹出登录框 `(QS4, 100, ZH, )` |
| `-system=DS4`（缺 `-client`） | 登录框客户端为空 `(DS4, , ZH, )`，需手填 → **`-client` 必须传** |
| `-type=System -system=DS4 -client=120` | 与不带 `-type` 等效，均正常（`-type` 既非必需也非有害） |

- **结论**：`sapshcut` 的 `-system=` 只认 **SID（DS4/QS4/PS4）**，连接项名（`DS4-120ZH`）不是它的合法取值。
  用户 11-17 说的「系统标识应该是 DS4/QS4 这种，客户端才带 120/110/100」**完全正确**，前两轮把它当成
  「SAP Logon 语义 ≠ sapshcut 参数层」是误判。SAP Logon 列表里「名称」列本来就是 `DS4`、`PS4 [PUBLIC]`、`QS4`，
  根本没有 `DS4-120ZH`（见 `docs/screenshots/` 之外的实机截图：登录框标题即 `(DS4, 120, ZH, )`）。
- **A 档（不传 `-pw`）的成功标志是 SAP Logon 的登录框**，不是 `sapgui.exe` 会话窗口：会话窗口要等用户输了
  密码、登录成功后才会出现。只扫 `sapgui.exe` 的旧判定必然误报。
- 修法：`resolve_launch()` 统一解析出 `{sid, client, language, source}`（连接项名也反查成 SID）；
  `argv = -type=System -system=<SID> -client=<client> -user=<user> -language=<lang>`；
  `_wait_sap_ready()` 以「`saplogon.exe` + 标题含 `SAP GUI 快捷方式 - 登录`」为成功，
  以标题含「SAP 快捷方式属性 / 系统条目属性」为失败（502 并回报对话框标题）；语言取自连接项，不再硬编码 ZH。
- **排查陷阱（坑了自己两轮）**：用 `WM_CLOSE` 强关登录框后约 0.6s，sapshcut 会弹一个**持久的**
  「SAP 快捷方式属性」空窗口。自动化脚本把它当成「启动失败证据」就会得出完全错误的结论 ——
  属性框有两种来源：参数 516 失败、以及强关登录框的残留。
- 回归：`verify_sap.py` **23/23**。真实启动 DS4|120 耗时 2.5s、`verified=true front=true`。

**③ 启动 SAP 时「密码复制失败」**

- 现象：SAP 能正常启动，但弹「复制失败：…」，剪贴板里没有密码。
- 根因：`openSap()` 原来是「先请求启动接口、**再**复制密码」。后端成功后会 `bring_to_front` 把 SAP 登录框置前，
  页面随即失焦；`navigator.clipboard.writeText` 要求文档持有焦点 ——
  在 Chrome 里实测会**挂起不 resolve**（Promise 永不结束，后续 `message.info` 整段不执行），
  在 WebView2 里则直接 reject（用户看到的「复制失败」）。
- 修法（`CredentialsView.vue`）：
  1. **先复制密码、再请求启动**（此时页面仍有焦点）；
  2. `writeClipboard()` 给 Clipboard API 加 **1.5s 超时兜底**，超时/被拒则回退 `document.execCommand('copy')`；
     `scheduleClear()` 的 `readText()` 同样加超时，避免 30 秒后清理时再次挂死；
  3. `copyField()` 改为返回 `boolean`，失败时明确提示「密码未能自动复制，请点上方「复制密码」后手动粘贴」，
     不再出现「已复制」与实际不符的假提示。
- 验证：用 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9223` 起真实 pywebview 窗口，
  CDP 真实点击「启动 SAP」：`writeText` 在 **3ms 内成功**（18 字符），时序为 `writeText@12455 → open-sap@12458`，
  两条提示均正常。工具保留在 `tools/probe_webview_copy.mjs`。
- 注意：**不要用后台 Chrome 窗口做这个验证** —— 系统级前台不是测试页面时 `document.hasFocus()` 也是 false，
  会得到「必然失败」的假象（本排查中踩过一次）。

### 2.25 OneNote 迁移：.onepkg → 记事本（2026-11-18）

- 输入：单文件 / **目录（整本，递归扫 `*.mht` / `*.mhtml`）** / 多文件 / 通配符。

- 重复导入同一节 → 分区自动加序号（`MM (2)`），页面不会混进旧分区。

### 2.26 记事本布局重构：顶部页签 + 双栏独立滚动（2026-11-18）

**用户诉求**：① 分区作为顶部页签固定显示，滚动条不能把页签滚走；② 左侧页面列表与右侧正文各自独立滚动，
右侧滚动时左侧不能一起滚没。先出静态原型确认，再改代码。

**根因**：外层 `.content` 是 `overflow: auto`，而 `.notes-layout` 只有 `min-height: 560px` 没有确定高度，
所以内容一长滚动就发生在最外层，左侧树跟着被卷走。

**结构**：`笔记本下拉 + ⋯ | 分区页签 | 导入 | +分区` 固定顶部；下方 `.notes-body` 分左右两栏。

- 根容器 `height: 100%; min-height: 0`，`.notes-body { flex: 1; min-height: 0 }`，
  左右子项各自 `overflow-y: auto` —— `min-height: 0` 是让 flex 子项能真正收缩出内部滚动的关键。
- `.tiptap` 原来的 `min-height: 320px` 必须改 `0`，否则会把父级撑开、滚动又跑到外层。
- **页签不放滚动条**：容器 `overflow: hidden`，用隐藏测量层（`position: fixed; left: -10000px`）
  量每个页签自然宽度，按容器宽度决定显示几个，其余进「更多 ▾」下拉；`ResizeObserver` 监听容器宽度变化。
  当前激活分区若被挤进「更多」，会换进可见区末尾，否则看不到激活态。
- 左侧固定 212px，只列**当前分区**的页面；分区切换时若当前页面不属于新分区则关闭，
  避免右侧留着别的分区的内容。切换笔记本同样关闭当前页。

**验证**：`tools/verify_note_layout.mjs`（新增）12/12 —— 右侧滚动后左侧 `scrollTop` 与页签 `rect.top` 不变、
外层 `.content.scrollTop` 恒为 0；左侧滚动时右侧不动；18 个分区时可见 8 个 +「更多」10 项；
页签无页数徽标。既有回归同步更新选择器后：`verify_note_ui` 11/11、`verify_note_import_ui` 11/11、
`verify_note_table_ui` 9/9、`verify_notes.py` 24/24。

**连带修复**：`onSectionContext` 原有「`closest('button')` 就 return」的判断——页签本身就是 button，
不改会导致右键删除分区失效，已移除。

**设计原型**：`docs/layout-preview.html`（静态可交互，保留作布局参考）。

### 2.27 SAP 启动三次反复后的最终结论（2026-11-18）

**现象**：`D:\OnlyOne\data\onlyone.log` 连续多次
`SAP 启动未出现登录窗口 key=DS4|120 -system=DS4 client=120 exit=0`。
日志里的 `client=120` 少个 `-` 只是文案笔误，实际 argv 是对的。

**最终结论：`-system=` 只认 SID（`DS4`），绝不能传连接项名（`DS4-120ZH`）。**

决定性证据来自用户 15:32 那次点击生成的 `sapshlib_1360.trc`：

```
Command: ' -type=System -system=DS4-120ZH -client=120 -user=10000265 -language=ZH '
Loaded from command line: ...
	[Function], 	Type=>System<
	[System], 	Name=>DS4-120ZH<
Getting Description according to System ID in SAP landscape file >DS4-120ZH<
Error in LoadAll: code = 516, Not all system data are available
Error in loading shortcut '...', code = 516
```

传连接项名的后果是弹出「部分数据不可用」错误框，而那个框的窗口标题恰好是 **`SAP GUI`**——
看起来像个刚打开的空会话，极易被判成成功（中途确实误判过一次 `verified=1`）。

**三次反复的认知轨迹**（都记在这里，避免再来第四次）：

| 时间 | 结论 | 对错 |
|---|---|---|
| 11-17 15:23 | 加 `-type=System` + 连接项名 | 参数方向对，但 `-system` 值错 |
| 11-17 18:20 | 去掉 `-type=System`，仍用连接项名 | 错（用户报同一个错） |
| 11-17 18:35 | `-system=<SID>` + `-client=` | **对**（当时已有 trace 516 证据） |
| 11-18 13:35 | 曾误改为传连接项名（据「传 SID 无窗口」的表象） | **错**，已改回 |
| 11-18 15:34 | 回到 SID，并用 trace 再次确认 | **最终** |

**「传 SID 无窗口」不是失败**：当该用户已有同系统会话时，SAP 会**复用**已有会话，
sapshcut 直接 exit=0、**不新开窗口、也不写 trace**。此时应判定为「复用」而不是「启动失败」。

**窗口识别（本次同步修正）**：
- `_is_session_window()`：允许 `saplogon.exe`（单进程架构），按「不是 Logon 主界面 /
  不是登录框 / 不是报错框」反选，并**排除标题恰为 `SAP GUI` 的占位窗口**（错误框就是这个标题）。
- `_is_login_prompt()`：只认标题不认进程。
- 新增 `_is_logon_window()`：识别 `SAP Logon 800` 这类主界面。

**验证**：`verify_sap.py` 23/23（「-system 只传 SID，不含连接项名」一条已固定）；
实测 `launch_connection('DS4|120')` 在已有会话时返回
`verified=false` + 「已复用当前会话并置前」且窗口置前，不再出现假成功或 502。

**教训**：判失败/成功必须以 **sapshlib 的 trace** 为准，并确认 trace 对应的是哪一次调用；
`-system=` 的语义在 SAP 文档里是 System ID，连接项名只是 SAP Logon 的快捷方式名字。

## 5. 关键技术事实（别重复踩坑）

1. **FTS5 trigram 对两字中文词失效**：必须保留 trigram + 短词/零命中 LIKE 兜底。
2. **DPAPI 的 `c_byte` 有符号**：`db.py` 已改 `c_ubyte`；安全边界是防文件外泄，不防同账户其他进程。
3. **WPS COM 格式常量**：Writer `.docx`=12（不是 16）、PPT `.pptx`=24、ET `.xls`=56；另存后校验 `PK\x03\x04`。
4. **统一条目写入责任**：业务表 / 文件 / 笔记任何写入都要调 `entries.sync_entry`（或 `notes._sync_note_entry`）；删除走对应 `drop_entry`。笔记的 `entries` 无外键，裸 SQL 删除 notebooks 前必须手动清 `entries` / `fts_entries` / `semantic_index`（`purge()` 已处理）。
5. **扫描串行化**：`scanner._SCAN_LOCK` + `wps_session()`（`threading.local()`）。
6. **打包路径**：`db._base_dir()` 在 frozen 时取 `sys.executable.parent`；`data/` 与 `frontend/dist/` 必须在 EXE 同级。
7. **回归脚本不可并发**：七个脚本共用 `data/onlyone.db`，必须串行。
8. **`npm --prefix` 在 Git Bash 不生效**：必须 `cd frontend && npm install`。
9. **Vue 模板坑**：`v-for` + 长 `v-else-if` 链会让 `vue-tsc` 报错 → 拆子组件；`NSelect` options 需显式 `SelectOption[]`。
10. **HTTP 头只能 latin-1**：`Content-Disposition` 文件名必须 ASCII，中文放内容里。
11. **本用户工程约定**：含中文路径下不要落地 `.ps1`/`.bat` 再执行；改代码 / 改配置 / 改文件前**先给方案、等明确确认再动手**；中文、结论先行、表格化、最小改动、便于回滚。
