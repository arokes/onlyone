# OnlyOne 应用图标设计方案

> 目标：为 OnlyOne 提供一套**同源三用**的图标 —— EXE 图标、窗口/任务栏图标、界面内品牌标。
> 现状：`build.py` 没有 `--icon`，`index.html` 没有 favicon，pywebview 也没有指定窗口图标 —— 三处目前都是系统默认。

---

## 一、缺口盘点（改造前）

| 位置 | 现在 | 用户看到 |
|---|---|---|
| `OnlyOne.exe` | PyInstaller 默认图标 | 资源管理器里是一个空白通用图标 |
| 任务栏 / 标题栏 / Alt+Tab | 继承 exe | 同上，且与「OnlyOne」这个名字没有任何视觉关联 |
| 浏览器标签（`--browser` 降级模式） | 无 favicon → 404 | 标签页显示浏览器默认地球 |
| 界面内品牌位 | 只有文字「OnlyOne」 | 无图形标识 |

三处必须**同源**：同一个矢量主稿导出不同尺寸，不各画一套。

---

## 二、设计目标与约束

1. **16px 能认**：任务栏和 Alt+Tab 的实际显示只有 16–24px。这是硬门槛，所有细节必须在此尺寸下要么保留要么主动删掉。
2. **深色/浅色任务栏都成立**：Win11 任务栏默认深色、资源管理器多为浅色。因此图标要**不透明实底**（不用透明背景 + 细线），否则换底就崩。
3. **和界面同色**：只用现有令牌 —— 墨蓝 `#1f3040`、暖纸 `#f4eee2`、陶土橙 `#bf5a36`。不引入新色。
4. **可辨识优先于可解释**：图标不是 logo 释义图。名字含义靠"形"传递，不靠画三个隐喻元素。

## 三、三个方向

### 方向 A「索引卡」

圆角方块（墨蓝）内放一张暖纸色卡片，右下角折角，折角处点一个橙色小块。

- 表达：一张自己的索引卡 / 一个本地文档库
- ✅ 和产品气质最贴（暖纸 + 纸质档案）
- ❌ **16px 下折角糊成一团**，卡片与底色的明度差在深色任务栏里也变弱
- 结论：适合做宣传图/启动图，不适合做应用图标

### 方向 B「O·1 连写」（推荐）

圆角方块（暖纸色）内一个墨蓝粗环 "O"，环的右侧缺口处插入一条墨蓝竖线（"1"），竖线顶端一个橙点。

- 表达：OnlyOne = O + 1，直接对应名字，不依赖隐喻
- ✅ 只有两笔，16px 仍然读得出；`O` 与 `1` 靠"环有缺口 + 竖线独立"区分，不会被读成 `01`
- ✅ 三色即界面三色，暖纸底在深浅任务栏上都干净
- ⚠️ 需要**两套画法**：32px 以上带橙点与缺口；16/20/24 去掉橙点、加粗环、缺口收窄（详见第五节）

### 方向 C「印章」

陶土橙实心圆，内白色「1」，外圈一道细描边。

- ✅ 单字最好认，气质"私人印记"，和"个人工作台"贴合
- ❌ 圆形在任务栏里视觉重量小于方形，显得小一号；橙色实底在深色任务栏偏跳；细描边在 16px 直接消失
- 结论：可作为社交头像/水印，不做主图标

### 取舍对照

| 维度 | A 索引卡 | **B O·1** | C 印章 |
|---|---|---|---|
| 16px 可认 | 差 | **好** | 中 |
| 与名字关联 | 弱 | **强** | 中 |
| 深/浅任务栏 | 中 | **好** | 中 |
| 与界面配色一致 | 好 | **好** | 中 |
| 制作成本 | 中 | **低** | 低 |

**推荐 B**，理由只有一条：它是唯一在 16px 下还能被认出来、并且能被读成"OnlyOne"的方案。

## 四、B 方案规格

**主稿 1024×1024**

| 项 | 值 |
|---|---|
| 底板 | 圆角矩形，圆角半径 **22%**（225/1024，偏 macOS 圆润） |
| 底色 | `#f4eee2` 暖纸（界面同色） |
| 主形 | `#1f3040` 墨蓝：扁椭圆 `rx208 ry222`（宽高比 0.94）+ 独立竖笔 |
| 分离 | 环外缘与竖笔之间 **留 45px 缝**（刻意不连写） |
| 强调 | `#bf5a36` 橙点，直径 100px，落在竖笔顶端 |
| 安全边距 | 四周 ≥ 175px（17%），保证小尺寸不被裁 |
| 禁止 | 渐变、投影、描边细节、超过 3 种颜色 |

**为什么是分离而不是连写**：O 与等高竖笔相连，在字形上等于小写 `a`（或 `d`、`q`），缩小后一定被读成字母。留缝是唯一可靠的区分手段，代价是失去"一体感"。

**尺寸与特调**

| 尺寸 | 画法 | 缝宽 | 环笔画 | 竖笔 |
|---|---|---|---|---|
| 256 / 128 / 64 / 48 | 主稿 | 45 | 80 | 72 |
| 40 / 32 | 加粗版 | 42 | 90 | 82 |
| 24 / 20 / 16 | 小尺寸版 | 30 | 116 | 112 |

> 经验规则：**能自动缩小的不叫图标，缩小后重新画的才叫图标。** 16px 必须是单独一版，不是 1024 缩放。

> 经验规则：**能自动缩小的不叫图标，缩小后重新画的才叫图标。** 16px 必须是单独一版，不是 1024 缩放。

**交付文件**

```
assets/icon/
  onlyone.svg            # 主稿（矢量，后续改色的唯一来源）
  onlyone-1024.png       # 源位图
  onlyone-256.png        # 关于页 / 文档用
  onlyone.ico            # 多帧：256,128,64,48,40,32,24,20,16
frontend/public/
  favicon.ico            # 16+32
  favicon-32.png
```

## 五、落地位置（三处，缺一处就不完整）

| 位置 | 改什么 | 说明 |
|---|---|---|
| `build.py` | PyInstaller 参数加 `"--icon", str(ROOT/"assets/icon/onlyone.ico")` | 决定 EXE 文件图标、任务栏、Alt+Tab、快捷方式 |
| `frontend/index.html` | `<link rel="icon" href="/favicon.ico">` | `--browser` 降级模式与开发时的标签页图标 |
| 窗口标题栏 | **无需单独设置** | pywebview 在 Windows 上用 exe 自带图标；跑 `run.py` 开发时看到的是 Python 图标，属正常 |

**注意**：PyInstaller 的 `--icon` 只影响 exe 的资源，不影响已存在的快捷方式 —— 换图标后旧快捷方式可能仍显示旧图标（Windows 图标缓存），需要重建快捷方式或清缓存。

## 六、验收

1. 资源管理器「大图标 / 中等图标 / 小图标 / 详细信息」四档都清楚
2. 任务栏（深色）与资源管理器（浅色）各看一眼，边界都在
3. Alt+Tab 缩略图里是 32px 版本，能认出是 O·1
4. 浏览器标签 16px 不糊
5. `dist/OnlyOne/OnlyOne.exe` 右键属性 → 详细信息里能看到图标
6. 关闭「显示文件扩展名」的机器上，图标不与 AnyDesk / OneNote 之类撞形

| 圆角 | **22%** |

**已落地**

- `assets/icon/onlyone.svg` / `onlyone-mid.svg` / `onlyone-small.svg` — 三版矢量
- `assets/icon/render_icons.py` — 一键出 9 尺寸 PNG + `onlyone.ico` + `favicon.ico`
- `assets/icon/onlyone.ico` — 9 帧（16…256），每帧独立渲染，非缩放
- `frontend/public/favicon.ico`、`favicon-32.png`
- `build.py` — `--icon` 已接，缺图标会提前报错
- `frontend/index.html` — 两个 `<link rel="icon">`

**打包验证（2026-11-19，实测）**

| 检查项 | 结果 |
|---|---|
| 打包 | `py -3 build.py --dist-dir dist_icon` 成功，111.3 MB / 389 文件 |
| exe 图标 | 从 `dist_icon/OnlyOne/OnlyOne.exe` 资源取出 32px，与源帧平均像素差 **2.93/255**（差值来自抗锯齿） |
| 多尺寸是否齐全 | exe 内 **RT_ICON 9 个 / RT_GROUP_ICON 1 组** —— 16~256 全在，不是只有 32 |
| 图标前后 | 旧 exe 是 PyInstaller 默认的 Python 图标，新 exe 是 O+1 |
| 应用可启动 | `OnlyOne.exe --no-window --port 8791` → `/api/meta/status` 200、`/` 200、`/favicon.ico` 200 |

**踩到的坑（下次照做）**

PyInstaller 的 COLLECT 阶段会先 `rmtree(dist/OnlyOne)` 再重建。若该目录里已有上一次的产物（三百多个文件），这一步会命中运行环境的批量删除保护：

```
[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED] count:321 threshold:50
```

这个阈值是**按轮次累计**的（不是按单次调用计），所以“分成每批 40 个删”同样会被拦。结果是打包失败、旧产物还被删了一半。

`build.py` 现在改成：**旧产物不删，改名挪到 `dist/OnlyOne.old-<时间戳>`**，PyInstaller 面对一个不存在的目录就不会触发删除；打完再尽力删掉那个 `.old`（删不动就留着，不影响结果）。失败时会把 `.old` 还原回 `dist/OnlyOne`。

**这不影响图标**——日志里 `Copying icon to EXE ... completed successfully` 始终在失败点之前。
